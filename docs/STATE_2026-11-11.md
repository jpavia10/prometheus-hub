# Prometheus: where things really stand (2026-11-11, Claude)

The owner's verdict on 2026-11-11: **"1.5/100. It's a bunch of placeholders with a bad UI."** This page is the honest
starting point for the next build. It replaces every earlier status claim, including Gemini's `STATUS_CLEAN_SLATE_v2`.

## 1. The spec

The owner's own brief is the spec: **"Prometheus revamp brief for Gemini Argon (2026-11-09).md"** (Drive, the Sebastian
folder, id `1QqyPm9qwEI_Wz_BPD_QzyHCSFDvjkmaO`, 32 KB). Read it whole before any work. In short:

- One futuristic command deck for the owner's life (not a directory of doors), with an **arrival view** that is his
  daily operating picture: time-critical first, money second, everything else ambient.
- 16 capabilities, each with a **proof** run on the live build: Time, Body, Trading journal, Mail, Money, House, Photos,
  Presence (Sylade), Selling, Piano, Garage, Bastion, Athenaeum, Odyssey, Privacy, Records.
- Integration is the product: every capability publishes its deadlines to Time, money events to Money, images to Photos.
- Hard rules: static hosting, no backend, data in the browser with **versioned JSON export/import on every capability**,
  no real balances anywhere (Midas's real book stays encrypted on its own origin), the journal never trades or advises,
  Fleet Command stays paused, Titan is a plain outbound link only, **no placeholder controls** ("a smaller finished thing
  beats a larger hollow one").
- Personal details in the brief (money, house, family, location) stay in Drive. This repository is public: never copy them here.

## 3. What not to trust

- **Gemini (Argon)'s `STATUS_CLEAN_SLATE_v2_20261109.md` marks all 16 capabilities DONE with "proofs". None of it is live.**
  Muse's review of the Argon package (Drive `NOTES_for_claude_argon-review_20261109.md`): one 286 KB JS file under four
  names (hub.js = kit = midas.js = hearth.js), one CSS file for three repos, 13 pillar pages that are the same 70 KB shell,
  and "proofs" citing files the package does not contain. Deploying it would have overwritten the live desk, Midas and
  Hearth. Do not deploy it. Worth keeping from it: `pillars.json` v2 (a 16-capability registry) and the single-origin
  argument in its `PLAN.md` (one origin = one local store = real cross-capability data flow).
- Gemini's notes of 2026-11-09 list Drive ids for pillar folders that do not exist (`1s8a9vR3gL2pK1wN4mX6bZ8cV0qT5yH7j`
  and similar keyboard runs). Open a file before you cite it.
- The 53 research deliverables are real and mostly verified (Sebastian, as acting integrator on 11-09, checked row
  counts against the originals and closed 53 tasks). They are raw material, not a product.

## 5. Suggested order for the next build

1. **One origin, one store** (`kit/bus.js` already does this for the hub and its pages): every capability reads and writes
   the bus; Midas stays apart.
2. **The arrival view** first: rebuild the desk as the operating picture from the bus (due within 7 days, the payoff
   instrument, the house project stage, practice streak, storm watch, vehicle dues), with away mode.
3. **Seed from truth**: each capability opens on the owner's real situation from the brief (labelled presets, editable),
   never on an empty form. Personal values come from the owner's Drive at run time or are typed by him, never committed.
4. **One capability at a time to its proof**, in the brief's order of value: Time, Money + Selling, House (the deck
   project), Garage, Records (school deadlines), Body, Journal, Mail, Piano, the rest. A capability is done only when its
   proof runs on the live URL.
5. **Visual identity** last per capability but before calling it done: the brief's bridge look, with the guardrails
   (60 fps on the phone, reduced motion, readable with every effect off).
